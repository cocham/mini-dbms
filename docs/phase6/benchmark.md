# Phase 6 대표 실험 — age 조건 페이지 조회, 선형 탐색 vs age 보조 인덱스

> 이 문서는 age 77로 진행한 이전 측정 기록입니다. 현재 기본값인 age 25의 결과는 [정리 문서](README.md)에 있습니다.

DB-P6-D11·D12에 따라 **변경 없는 같은 데이터**에서 같은 요청 하나를 두 경로로 실행했다(2026-11-18).
같은 실행 파일·데이터·설정이고, 다른 것은 서버 옵션 `--age-path scan` / `--age-path index` 하나다.
네 가지 분포 전체 실험, 쓰기 시간·메모리 측정은 하지 않았다.

## 환경

| 항목 | 값 |
|---|---|
| 실행 | Docker Desktop 28.5.1(WSL2, 커널 6.18.58.1), 이미지 `gcc:13`(GCC 13.5.0), 컨테이너에서 보이는 CPU 8개 |
| 빌드 | 소스를 컨테이너 안으로 복사해 `make age-bench`로 빌드(`-O2`). 데이터는 컨테이너 안 `/tmp`(Windows 공유 폴더를 피함) |
| 클라이언트 | `tools/age_bench.py`(Python 3.11.2), 서버와 같은 컨테이너, 127.0.0.1 |

**읽을 때 주의:** 응답 시간에는 파이썬 처리·TCP 연결(요청마다 새 연결)·JSON·전송이 들어 있다. 클라이언트와 서버가 같은 컨테이너에서 CPU를 나눠 쓴다. 숫자는 이 환경에서의 비교로만 읽는다. E는 행 확인 횟수이지 디스크 I/O 횟수가 아니다.

## 재현

```bash
MSYS_NO_PATHCONV=1 docker run --rm -v "$(pwd -W)":/src:ro gcc:13 bash -c   "mkdir /w && cd /src && tar --exclude=./build --exclude=./data --exclude=./.git -cf - . | tar -xf - -C /w    && cd /w && make age-bench AGE_COMMIT=<커밋>"
```

## 관찰과 해석

**관찰(위 표의 값):**
- 두 경로의 응답 본문은 바이트 단위로 같았다(100행, `has_more: true`, `next_cursor: 99001`, 2,473바이트).
- 파일에서 읽고 확인한 행: scan 100,001(그중 마지막 반환 행 뒤 1,000), index 100. index는 age 인덱스 항목 101개를 봤다.
- 클라이언트 응답 시간 중앙값: scan 7.259·8.221 ms(실행 1·4), index 0.496·0.425 ms(실행 2·3). 경로별로 합치면 scan 7.872 ms, index 0.471 ms(각 60회).
- 엔진 시간 중앙값(참고): 경로별 scan 6,992 µs, index 181 µs.
- 같은 경로의 두 실행 사이에도 응답 중앙값이 13~17% 달랐다(scan 7.259 vs 8.221, index 0.496 vs 0.425).

**해석(추정, 따로 재지 않음):**
- 파일 행 확인은 약 1,000분의 1로 줄었지만, 응답 시간 중앙값은 약 17분의 1, 엔진 시간은 약 39분의 1로 줄었다. 검사량이 줄어든 배수만큼 시간이 줄지는 않았다.
- 응답 시간이 덜 줄어든 이유는, 연결·파이썬 처리·JSON·전송처럼 경로와 상관없는 비용이 그대로 남아서일 것으로 추정한다. index의 응답 0.47 ms 중 엔진 시간은 0.18 ms다.
- index 경로는 행마다 id 인덱스 탐색과 따로 떨어진 위치의 한 줄 읽기를 한다. 그래서 행 하나당 비용은 scan의 연속 읽기보다 클 수 있다. 이번 실험은 단계별 시간을 재지 않았으므로 이 비중은 모른다.
- 이 결과는 드문 조건(0.1%)·첫 페이지 하나에 대한 것이다. 흔한 조건이나 다른 위치의 페이지, 쓰기가 섞인 부하에서도 같은 비율이라고 말할 수 없다.

**재지 않은 것:** 쓰기(INSERT·UPDATE·DELETE) 시간, age 인덱스의 메모리, 시작 시간 차이. `--age-path`는 읽기 경로만 바꾸고 age 인덱스는 양쪽 모두 유지하므로, 이 실험으로는 이 비용들을 비교할 수 없다. 서버 시작 줄의 시작 시간(138~195 ms)은 두 경로 모두 인덱스를 만드는 같은 코드다.
